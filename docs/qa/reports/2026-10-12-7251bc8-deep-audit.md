## Confirmed technical defects and fixes

### QA-101 — P1: zero-exit script errors can produce a false green gate

Godot previously returned exit zero for a failed GDScript load, as demonstrated by the earlier PR16 replay log. `check.sh` relied solely on exit status. A parse failure could therefore be followed by `SCALFAGUS_GODOT_CHECK_PASS`.

`scripts/godot-qa-run.sh` now preserves child exit codes and additionally rejects script errors, assertions, failed script loads and explicit Scalfagus FAIL markers. Every Godot invocation in `check.sh`, including import, passes through it. Regression tests explicitly exercise an exit-zero parse-error producer, a valid producer and a nonzero producer. Existing renderer teardown warnings remain visible rather than silently filtered.

### QA-102 — P1: addon verification mistakes generated metadata for source tampering

Godot rewrites `.import` metadata for platform and rendering settings. The addon inventory compared this generated metadata byte for byte with the upstream checkout, repeatedly flagging State Charts as incomplete and recopying it on the next check.

Verification now excludes `.import` metadata only. Script, source asset and license byte comparisons and pinned revision checks remain. A real import followed by addon inventory returned zero. This is not an exemption for modified addon source code.

### QA-103 — P1: macOS universal/arm64 export configuration invalid

The previous export reported ETC2/ASTC disabled in addition to missing templates. The project now enables `textures/vram_compression/import_etc2_astc` and includes the corresponding regenerated texture metadata. The configuration complaint disappeared from the new export attempt. Missing templates still block export; no export PASS is claimed.

## Codebase and design assessment

The useful MVP boundary is `MirrorMatchState`: fixed-tick domain state, ownership checks, finite Matter bookkeeping, construction/production and victory. `MirrorGeometry` defines 3x3 occupancy and 2m scale; `MirrorNavigationPort` wraps native AStarGrid2D; physics LOS belongs to renderer diagnostics. This follows DEC-034's separation of engine mechanisms from game authority. Compiled Verdant topology has one authored YAML source and a checked JSON artifact.

The automated acceptance suite checks 20Hz timing, 10 deposits / 1660 Matter, nine occupied cells / twelve building access cells, and the 49 tree / 148 water physics fixtures. These test results validate the covered cases; they do not prove arbitrary command sequences or cross-platform lockstep.

### Release gap — P0: DEC-033 Human-Human requirement

DEC-033 explicitly requires Human-Human with two clients and an authoritative LAN/loopback host. Current main supplies Human-Bot and Bot-Bot; no ENet match transport was found in `apps/game/scripts`. Human-Human is therefore a release-scope requirement still unimplemented, not an optional future feature. This corrects the broad scope wording of the earlier QA report.

### Replay gap — P1: state hashing is not command replay

`issue_command` records tick, owner, actor and action, but omits the command argument. Move destinations, gather source IDs and attack targets cannot be reconstructed from that event history. Equal-seed Bot-Bot results prove determinism on this pinned runtime; they do not prove playback of a human command recording. A parallel remote branch named `feat/mvp0-authoritative-command-gateway-20261012` exists; inspect and test it before implementing another gateway. It was not merged or assumed to be working in this audit.

### Construction gap — P1 / requires explicit semantics

An accepted Barracks command debits Matter immediately and stores progress on its worker. Stop/move/gather can replace that worker's order; there is no persistent worksite actor or resumable ledger independent of the worker. Worker death also removes that progress. Conservation can remain true because the amount stays in `spent_matter`, while the playable work disappears. Do not silently introduce refund, salvage or cancellation rules. First reconcile the MVP contract with post-MVP construction decisions, then test repeated orders, cancellation, worker death and recovery.

### Additional limits

- Renderer leaks remain in legacy smoke teardown: four ObjectDB/RID instances per affected invocation. The runner reports them but does not convert them into script failures.
- Mobile movement does not generally prevent two moving actors occupying one cell; distinct group destinations alone do not prove collision-safe transit. Determine the intended mobile collision contract before changing behavior.
- Four GUT tests are a narrow authority/input sample, not comprehensive integration coverage.
- Existing camera debug modes do not imply FPP/TPP release acceptance. DEC-033 excludes those modes from MVP0. ORG/ETH, UMU, academies and Titans are design scope for later releases under DEC-035–046.
