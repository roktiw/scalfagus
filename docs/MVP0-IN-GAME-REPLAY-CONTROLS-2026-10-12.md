# Scalfagus — Save Replay / Watch Replay (Human vs Bot)

**2026-10-12 · format-2 integration · GUI QA on this feature branch not yet executed**

## Player experience

1. Start **Play against computer**.
2. Play and give normal orders; every accepted **and rejected** human attempt is recorded with its tick, typed argument and result by `MirrorMatchState` (the PR #23 gameplay layer).
3. Press **Esc / Menu** and choose **Save replay**. The match remains paused; a status message confirms success/failure. The game writes **`user://replays/last-human-match.json`** using native Godot `FileAccess`. This is a **snapshot-to-current-tick** replay; saving before the final battle is valid.
4. Return to the main menu. **Watch last saved replay** becomes available only if a save exists.
5. The map opens in read-only replay mode with original human-vs-bot seed/controllers and the human player's fog of war. Input for issuing orders is disabled; the world simulates forward at 20Hz and reissues the stored human commands at their original ticks.
6. At the saved tick, the replay checks the final SHA-256 simulation state hash and independent SHA-256 ordered human-command history integrity (v2). It stops with **REPLAY VERIFIED** or **REPLAY DIVERGED: reason**; there is no silent fallback to a new game with different rules/map.

The in-game replay is not a video. It recreates the original deterministic match: all units and buildings come from the same Godot game state, using the same original pixel-art assets. No new graphic assets are introduced.

## Implementation boundaries

- `MirrorReplayArchive.prepare` validates **format_version=2**, source map, rule revision, controller ownership, data types, nondecreasing command ticks and independent `commands_hash` (including rejected attempts) **before leaving the current menu**. Malformed files fail with a visible reason.
- `MirrorReplaySession.begin/step` performs a single tick of playable replay at a time, with bot actions generated by the pinned deterministic policy and human attempts applied before each `sim.advance()`.
- `mirror_view.gd` reuses its existing scene/camera/selection pipeline and the command deck from PR #22. **Replay mode blocks user orders** in both hotkey/mouse routing and the HUD action buttons; camera, speed and pause still work.
- `menu.gd` offers a read-only replay entry if the saved file exists. The native Pause overlay adds one Save button for a real human match, not spectators or replay viewers.
- QA may set a separate validated `scalfagus/replay_basename` to avoid replacing a personal file. Production defaults to `last-human-match`. Filenames are ASCII allowlisted.
- No gameplay balancing, new unit art, source map, LAN transport or replay-network authority has been added.
- **Dependencies:** stacked on PR #22's native menu/HUD. PR #23 is now **merged into main** after a full Mac Godot QA. Its tested format-2 archive, lifecycle test and QA report have been incorporated. Integrate PR #21 → #22 first without reverting their UI fixes; never downgrade replay to v1.

## Latest integration hardening

- Complete-game replays execute the terminal tick and its last human attempts **even after `sim.finished`**; the viewer verifies both checksums rather than stalling one tick early.
- The main menu validates v2 before switching scenes. Malformed metadata or an incorrect `commands_hash` leaves the menu in place and shows the structured reason.
- Synthetic GUI QA uses a unique process/timestamp basename and never overwrites `last-human-match.json`.
- **Combined GUI QA has not run on Mac yet.** See the PR #23 report for backend-only evidence.
